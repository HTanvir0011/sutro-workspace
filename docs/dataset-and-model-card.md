# Dataset and model card

Date: 2026-10-15. Counts were measured on the local dataset bundle (see `docs/workspace-audit.md` and `data/manifest.json`); the bundle itself is not in the repository (size), only samples under `data/samples/`.

## A. Datasets

### A1. `khatian_form5462` — synthetic Bangla khatian pages (eligible; used)
- **What:** 5,794 page images (train 4,645 / val 570 / test 579) in the layout of Bangladesh *Form 5462 (revised)*: nine-column table, header block (division, district, thana, mouza, JL, khatian and sheet numbers), owner blocks (`দং` / `পিং-` / `সাং-` lines), 3-decimal shares that sum to exactly 1.000, per-dag rows (dag no., land class, total area in acre/decimal, share of this khatian in the dag, proportional area, remarks), total-land footer. Rendered from four Bengali font families with simulated scanning (paper tint, uneven light, noise, blur, rotation ≤ 1.3°, JPEG). Every page carries SYNTHETIC marks.
- **Labels:** `annotations.jsonl` — 318,988 field boxes (polygons in final image coordinates, rotation applied; boxes come from the live layout, not estimated) and 150,644 ruled lines; CSV tables `lands` (2,000), `khatians` (5,794), `owners` (23,120), `dag_rows` (31,572), `title_line` (3,794).
- **Title lines (RS/BS pairing):** every *land* has 2–4 khatian versions in survey order (CS 1,104 / SA 1,775 / RS 1,776 / BS 1,139). Consecutive versions are linked in `title_line.csv` with the transition (inheritance 593, sale 236, both 164, none 146 for RS→BS) and the exact owner shares as ground truth. Splits are by land (0 lands in more than one split).
- **OCR line crops:** 107,475 (train 86,132 / val 10,542 / test 10,801), height 40 px, 15 field types, charset of 64 Unicode code points; packed per split in `ocr_cells_packed/`.
- **Provenance:** generated by `tools/khatian_data.py` + `tools/khatian_render.py` (in the bundle). The layout and terminology were modelled on one real RS khatian supplied by the project owner; **nothing from that sample's data, seal or signature is reused**; all names, numbers and places are invented. Inheritance transitions use the same narrow Hanafi case the engine supports (and an *illustrative* equal split for Hindu families, marked as such).
- **Licence:** MIT (generated). Fonts: Hind Siliguri, Noto Sans/Serif Bengali (OFL); Nirmala UI (Windows system font, not redistributed).
- **Limitations:** printed-text renders, not handwriting, not real scans; one layout applied to all four survey labels; no smudges/hand corrections/torn margins; Latin numerals are not used (Bangla digits only).

### A2. Sutro case packets — synthetic (eligible; used)
20,000 packets (16,000 / 2,000 / 2,000) with 19 injected fault types and the expected finding codes; relational CSV tables; 57 importable samples in `data/samples/packets/`. The engine agrees with all 20,000 labels (`_verify_report.json`) — a **self-consistency check**, not a benchmark, because the generator and the engine share an author and the rules.

### A3. NumtaDB — real handwritten Bangla digits (eligible public open data; used)
Kaggle `BengaliAI/numta`, **CC BY-SA 4.0**. Converted to `numta_32x32.npz`: 64,841 train + 7,204 validation images, 32×32 grayscale, ink bright, balanced 10 classes, source-set tag a–e kept. Writer identities are not available, so the split is by image (writer leakage cannot be excluded — disclosed). The trained digit model is a derivative and is shared under the same licence.

### A4. DIU Bangla Handwritten Dolil Dataset — real deed scans (**not eligible without organiser approval; not used**)
653 scans, CC BY 4.0, Mendeley doi:10.17632/yk3c3xy9vm.1. They are real handwritten land deeds that may contain personal data; competition rulebook §8 forbids using or displaying real records without full anonymisation and prior organiser approval. Kept out of the app, the repository and the training data (present only in the local bundle, flagged there).

### Not available
No public RS/BS/CS/SA khatian dataset (images or CSV) exists: the only research release found (KhatianDoc, 107 RS khatians) had an empty Hugging Face repository when checked on 2026-10-15. Government portals allow single lookups only and may not be scraped (rulebook §8).

## B. Models

Both models are **input assistance only**: they suggest text that a person confirms; the audit engine is deterministic and uses no model. Both are exported to ONNX (opset 17) with a parity check against PyTorch and run in the browser with ONNX Runtime Web. The site reads the numbers below from `artifacts/runs/<run-id>/` — nothing is typed in by hand.

### B1. Khatian text-line reader — `notebooks/01_khatian_cell_ocr_crnn.ipynb`
- **Task:** read one cropped text line from a Form-5462-style page (names, father/village lines, dag numbers, land class, areas, shares, remarks, admin names).
- **Data:** A1 OCR crops, split **by land**; dataset hash, counts and a leakage assertion are written to `dataset_manifest.json` / `split_manifest.json`.
- **Model:** CRNN — 6 conv blocks (BN, ReLU) → 2-layer BiLSTM(256) → linear, CTC over Unicode code points (conjuncts are code-point sequences; no tokenizer). AdamW + OneCycle, AMP on GPU, light augmentation (width 0.9–1.1, rotation ±1.2°, contrast/brightness jitter, noise). Model selection by validation CER; one evaluation on the test split.
- **Metrics reported:** character error rate, exact match, per field type, inference ms/line, training curves.
- **Results (run `khatian-crnn-20261014-215159`, Kaggle GPU, 30 epochs, seed 42, 6.10 M params):** held-out test split of 10,801 lines (579 pages of lands never seen in training) — **CER 0.0000, exact match 100.00 %** for every one of the 15 field types; best validation CER 1.2e-5. Inference 2.21 ms/line on the training GPU. ONNX parity vs PyTorch max |diff| 7.6e-6. Full artifacts: `artifacts/runs/khatian-crnn-20261014-215159/`; this run is the one active in the app.
- **Read the perfect score correctly.** The test pages come from the *same generator* as the training pages: the same four fonts, the same degradation model and a vocabulary of a few dozen invented names, places and land classes. A score this high means the pipeline is implemented correctly and the model has learned that distribution; it does **not** mean the reader will work on real scans, other fonts, handwriting or names it has never seen. That is exactly why the number is labelled "synthetic distribution only" wherever it is shown, and why nothing enters a case without user confirmation.
- **Limitations:** synthetic printed text only; accuracy on real scanned or handwritten khatians is **not measured**; charset limited to training characters; no layout detection (lines must be cropped first); greedy decoding, no language model.

### B2. Bangla digit classifier — `notebooks/02_numta_digit_cnn.ipynb`
- **Task:** classify one isolated handwritten Bangla digit (০–৯), 32×32.
- **Data:** A3; validation slice carved into validation (model selection) and test (final number) halves with a fixed seed.
- **Model:** small CNN (3 × [conv-BN-ReLU ×2, pool, dropout] + MLP), AdamW + OneCycle, affine/noise augmentation, label smoothing 0.05.
- **Metrics reported:** accuracy, macro-F1, per-class precision/recall/F1, confusion matrix (raw / row-normalised), per-source-set accuracy, inference ms/image.
- **Results (run `numta-cnn-20261014-215200`, Kaggle GPU, 20 epochs, seed 42):** held-out test slice of 3,602 images — **accuracy 99.31 %, macro-F1 99.31 %** (validation accuracy 99.50 %); per NumtaDB source set: a 99.68 %, b 100 % (n=24), c 99.52 %, d 99.28 %, e 98.59 %; lowest per-class F1 98.74 % (digit ১). Inference 0.92 ms/image on the training GPU (not measured in the browser). ONNX parity vs PyTorch max |diff| 1.4e-6. Full artifacts: `artifacts/runs/numta-cnn-20261014-215200/`; this run is the one active in the app.
- **Limitations:** isolated digits only; no multi-digit segmentation; performance on digits cropped from real khatians **not measured**; softmax outputs are not calibrated probabilities.

### Local smoke runs (not results)
`notebooks/run_local.py` with `SMOKE=1` executed both notebooks end-to-end on CPU (1–2 epochs on a few thousand samples) to check the code and the artifact format. Their numbers (CER 1.0; digit accuracy ≈ chance) are **not** reported anywhere as results and are marked `smoke` in `metrics.json`.

## C. Reproducibility
Seeds: dataset generators 2026; notebooks 42. Configuration, dataset hash, split membership and history are written per run. Training commands: `docs/runbook.md`. Import: `node scripts/import-run.js nb01|nb02 --activate` (never overwrites an existing run; records a run without `metrics.json` as *failed*).
